# AI 编码与审查规则

> **用途：** 定义 UniPass 的红绿灯审查、客观验证和交付规则。入口见 [AGENTS.md](../AGENTS.md)，当前状态见 [CONTEXT.md](../CONTEXT.md)。

## 1. 红绿灯审查系统（Traffic Light Audit）

每次完成源码、构建、CI、权限或安全边界改动后，必须先执行审查，再运行客观验证。审查结论使用以下格式：

```markdown
## 🚦 Audit Report

**总体评价：** [ 🔴 阻断 / 🟡 可通行 / 🟢 绿灯 ]

**1. 🔴 阻断项（必须修复）：**
- 无 / 具体问题、位置和修复要求

**2. 🟡 优化项（可跟踪）：**
- 无 / 具体风险、影响和跟踪位置

**3. 🟢 已确认项：**
- 已满足的关键边界和验证准备

**4. 👮 下一步：**
- 修复阻断，或执行明确的验证命令/人工验收
```

### 审查维度

1. **真实性与用户意图**：引用的 API、manifest 权限、消息类型和页面行为是否真实；是否把构建通过误报为登录态验收通过。
2. **凭据最小暴露**：列表渲染不得批量把明文密码发送到 Popup；密码、Jupiter token 不得落盘、写日志或进入错误消息。
3. **页面边界**：只向 HTTPS 且匹配应用的页面填充；标签页切换后重新校验；不自动提交；不常驻注入。
4. **权限与网络**：manifest 权限和 host permissions 保持最小化；新增外部域名、存储或后台行为有文档、失败处理和回滚理由。
5. **会话与缓存**：缓存按用户隔离、有 TTL；部分失败不得覆盖完整目录；登录失效、网络超时和服务端格式异常有可读结果。
6. **架构与可测试性**：Popup、Service Worker、Content Script 和 shared 模块职责清晰；关键 URL、版本、缓存和错误分支可测试。
7. **发布一致性**：`package.json`、manifest 和 tag 版本一致；CI 不跳过治理检查、测试、类型检查或构建。

### 分级标准

| 等级 | 含义 | UniPass 典型情形 |
| --- | --- | --- |
| 🔴 红灯 | 必须修复后才能完成或发布 | 明文凭据/token 持久化或日志泄露；允许 HTTP/任意站点填充；自动提交；权限无理由扩大；部分目录冒充完整结果；验证失败或被绕过 |
| 🟡 黄灯 | 功能可通行，但必须明确记录 | 真实登录态未验收；短期缓存存在可接受陈旧窗口；外部接口缺少自动化集成测试；单文件职责过重；文档尚待同步 |
| 🟢 绿灯 | 无已知阻断，可进入验证或交付 | 安全边界保持、错误路径清晰、测试覆盖与相关文档同步 |

红灯不得用“后续优化”降级。可跨任务跟进的黄灯写入 [TECH_DEBT.md](TECH_DEBT.md)；影响当前阶段的红灯在 [CONTEXT.md](../CONTEXT.md) 只保留 ID 和一句摘要。

## 2. 代码规模触发项

- 单个源码文件超过 350 行：审查必须说明是否仍保持单一职责。
- 超过 500 行：默认 🟡，继续加功能前给出拆分方案。
- 超过 650 行：除低复杂度静态数据外默认 🔴，应先拆分。

## 3. 审查与验证顺序

```text
读取 CONTEXT / LESSONS → 按需读取专题文档 → 实现 → 🚦 Audit Report → 客观验证 → 更新唯一事实源 → 交付
```

- 默认完整验证为 `npm run verify`。
- 只改治理文档时至少运行 `npm run docs:governance:check`；同时改源码、脚本或 CI 时仍运行完整验证。
- 客观项必须给出真实命令和结果。真实账号、浏览器安装、Cookie、Jupiter 重启保活等人工项明确标为“未验收”或记录日期与环境。
- 修改 release 流程时另运行适用的 `scripts/verify-release-version.mjs` 检查。
- 未经用户明确要求，不自动 commit 或 push；不得因绿灯擅自修改 Git 历史。

## 4. 文档更新路由

- 当前阶段、阻断、前三优先级、最后验证：`CONTEXT.md`
- 安全边界、权限与敏感数据生命周期：`SECURITY.md`
- 架构职责与数据流：`docs/ARCHITECTURE.md`
- 可跨任务黄灯：`docs/TECH_DEBT.md`
- 长期决策及其原因：`docs/ADR/*`
- 治理规则：本文；不要在 README 或 PR 模板复制完整规则
