# 治理文档维护规则

## 目标

治理文档用于快速定位真实约束，不充当逐次工作日志。遵循单一事实源、按需加载、可验证预算和可归档历史。

## 事实源与职责

| 事实 | 唯一权威位置 |
| --- | --- |
| AI 入口、读取路由、硬边界 | `AGENTS.md` |
| 当前阶段、阻断、前三优先级、最后验证 | `CONTEXT.md` |
| 可复发经验路由与详情 | `LESSONS.md`、`docs/lessons/*` |
| 红绿灯、验证和交付规则 | `docs/AI_RULES.md` |
| 运行时架构与消息边界 | `docs/ARCHITECTURE.md` |
| 凭据、权限、存储和网络安全 | `SECURITY.md` |
| 活跃技术债 | `docs/TECH_DEBT.md` |
| 长期架构决策 | `docs/ADR/*` |
| 用户安装、使用与发版入口 | `README.md` |

## 强制加载预算

`npm run docs:governance:check` 同时检查行数与字符数：

| 文件 | 最大行数 | 最大字符数 |
| --- | ---: | ---: |
| `AGENTS.md` | 80 | 4,800 |
| `CONTEXT.md` | 45 | 2,800 |
| `LESSONS.md` | 20 | 1,600 |

## 更新规则

1. 先判断事实所属文档，只更新一处；其他位置只保留链接或面向不同受众的摘要。
2. `CONTEXT.md` 只在阶段、阻断、前三优先级或最后验证变化时更新，不记录分支、逐提交日志或完整债务。
3. 黄灯需要跨任务跟进时登记技术债；一次性发现或已立即修复的问题不制造债务条目。
4. 已完成债务和长复盘移入 `docs/archive/` 或交给 Git 历史；活跃文档只保留可行动事实。
5. 新 lesson 只记录可复发且会改变行动的结论；实现细节留在代码、测试或 ADR。
6. 修改权限、敏感存储、凭据流或 host permissions 时，必须同步 `SECURITY.md`；长期边界变化另写 ADR。

## 变更验收

治理文档改动后运行 `npm run docs:governance:check`，人工确认链接有效、事实没有互相冲突、`CONTEXT` 优先级不超过三项。源码、脚本或 CI 同改时运行完整 `npm run verify`。
