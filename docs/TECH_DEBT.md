## 分级

| 等级 | 含义 | 处理要求 |
| --- | --- | --- |
| P0 | 正确性或安全阻断 | 当前任务修复；影响阶段时在 `CONTEXT.md` 标记 |

## 未偿还债务

### TD-001: Popup 职责拆分

- **等级：** P1
- **位置：** `src/popup/popup.ts`
- **问题：** 文件已超过 500 行，同时承载初始化、主题、版本设置、目录缓存、URL 匹配后的展示、账号操作和凭据面板逻辑。
- **影响：** 新功能容易扩大共享状态和异步竞态，单元测试难以覆盖 UI 编排。
- **建议：** 按 `catalog`、`credentials`、`settings/theme` 拆分模块，DOM 绑定保留在入口；不改变跨上下文消息契约。
- **验证：** `npm run verify`，并在真实 Popup 覆盖当前页面、全部应用、设置弹窗和凭据倒计时。

### TD-002: 真实登录态与 Jupiter 生命周期验收

- **等级：** P1
- **位置：** `src/background/service-worker.ts`、`src/popup/popup.ts`
- **问题：** 自动化覆盖 URL 和 API 纯逻辑，但无法模拟真实 Chrome Cookie、Service Worker 重启、alarm、标签页注入和 UniPass 用户切换。
- **影响：** 登录失效、浏览器重启或切换 UniPass 用户后，Jupiter 托管可能出现状态陈旧或需要人工重新启用。
- **建议：** 建立手动烟测清单；确认用户切换是否应自动关闭托管或把设置绑定到 UniPass 身份，再决定是否新增身份隔离。
- **验证：** 记录 Chrome 版本、UniPass/Jupiter 账号、重启/登出/切换步骤和结果；不得记录密码或 token。

## 偿还流程

1. 红绿灯或用户反馈识别问题并分级。
2. 修复时补测试或明确真实浏览器验收。
3. 完成后从活跃清单移除；需要保留复盘时移入 `docs/archive/tech-debt/`，Git 历史保留变更依据。
