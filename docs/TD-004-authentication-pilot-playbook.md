# TD-004 认证服务端化试点准备手册

> **状态：** 决策前准备及人工盘点/验收已由维护者于 2026-09-09 确认完成；等待已确认协议和接口契约交接后实施。
>
> **目的：** 为逐应用移除客户端长期凭据解密准备可比较、可审计的输入。本文件不预先选择协议、不构成接口契约，也不授权在扩展中保存客户端 secret。

## 1. 适用范围与完成标准

试点目标是让一个目标应用的登录不再要求 UniPass 向扩展交付可复用密码。可接受的目标包括受限 OIDC/SAML 单点登录、一次性 token exchange，或由 UniPass 服务端代换并启动的短期会话。

试点完成不等于只完成“能登录”。已迁移应用必须同时满足：

- 授权由服务端基于 UniPass 用户、应用和账号判断；扩展不能用公开 extension ID、版本号或内置常量充当授权。
- 会话凭证短期、单次使用，并绑定用户、应用、目标 HTTPS origin 和扩展生成的 nonce。
- 服务端拒绝错误用户/账号/origin、过期和重放；支持撤销、限流及脱敏审计。
- 扩展产物不再包含该应用的 `PASSWORD_KEY`、解密调用或可复用密码响应处理。
- 保留可关闭的功能开关和已验证的密码型回退；真实 Chrome 完成成功、失败、撤销、切换用户和回退验收。

## 2. 人工能力盘点表

由 UniPass 后端负责人和每个目标应用负责人共同填写；不要粘贴真实密码、token、完整 Cookie、完整 SAML assertion 或生产响应。

| 字段 | 填写说明 |
| --- | --- |
| 应用名称与负责人 | 应用、技术负责人、业务/安全审批人和联系渠道 |
| 目标地址 | 仅记录 HTTPS origin；路径规则另列，避免收集用户实际访问 URL |
| 当前认证方式 | 密码表单、OIDC、SAML、企业 SSO、已有 token exchange 或其他；附脱敏流程图 |
| 身份提供方与协议能力 | 支持的 grant/断言流程、issuer、客户端注册方式、回调/受众限制 |
| 可承载一次性会话的入口 | 授权码回调、后端 exchange、受限跳转页或其他；说明是否需应用改造 |
| 绑定能力 | 能否校验 UniPass 用户、账号、应用、目标 origin、nonce、`exp` 和 `jti` |
| 撤销与生命周期 | 最短可配置 TTL、单次消费存储、用户退出/禁用后的失效传播时间 |
| 审计与限流 | 可记录的脱敏字段、查询留存期、按用户/IP/应用的限流与告警 |
| 回退与关闭 | 功能开关位置、回退条件、负责人、预计恢复时间 |
| 测试条件 | 脱敏测试账号、非生产环境、浏览器验收负责人、可安排窗口 |
| 阻碍与决定日期 | 缺少的权限/配置、风险、最终是否进入试点及日期 |

## 3. 试点选择规则

先排除必须把长期客户端 secret 或可复用密码交给扩展的方案。对其余候选应用按下表评分；任一“硬门槛”为否即不进入本轮试点。

| 维度 | 硬门槛/评分依据 |
| --- | --- |
| 服务端可控性 | **硬门槛：** UniPass 后端负责人可改鉴权、撤销和审计；目标应用负责人可配置认证入口 |
| 一次性会话能力 | **硬门槛：** 可在服务端消费 `jti`/nonce，且可设短 TTL |
| 目标绑定 | **硬门槛：** 能精确绑定应用与 HTTPS origin；不能只信任公开扩展标识 |
| 用户体验 | 登录路径不需要扩展读取 Cookie、授权码或页面私密数据；失败有明确人工接管路径 |
| 撤销与可观测性 | 能在用户退出、切换或撤权后停止后续 exchange，并提供脱敏审计 |
| 改造成本 | 优先选择已有 OIDC/SAML/SSO 或服务端 exchange 的应用，避免首个试点即改造遗留密码表单 |

建议选择“后端可改、已有现代认证入口、可提供测试环境和负责人”的最小应用。不能迁移的纯密码系统继续遵守现有最短生命周期、用户触发、精确 URL 和不持久化边界，不把其列为无密码试点。

## 4. 待决接口契约清单

在试点确定且 ADR 获批前，以下内容只能作为待回答问题，不能直接实现：

1. 服务端端点、调用方身份和传输方式分别是什么？扩展不得持有长期 client secret。
2. 授权输入如何表达 `userId`、`appId`、`accountId`、`targetOrigin` 和随机 `nonce`？这些值中哪些由服务端从会话推导，哪些需要严格校验？
3. 一次性会话采用何种形态（短期授权码、签名断言、受限跳转或服务端代换）？有效期、`jti` 去重存储和并发消费语义是什么？
4. 目标应用如何验证 issuer、audience、origin、签名/传输完整性和过期？如何拒绝重放？
5. 用户退出、账号移除、管理员撤权和应用禁用分别如何立即失效？失效传播 SLA 是什么？
6. 哪些事件写审计日志？日志如何只保留请求 ID、结果、时间、脱敏主体和错误类别，而不含密码、token 或完整响应？
7. 功能开关、灰度范围、回退条件和紧急关闭责任人是什么？
8. 错误码怎样区分“需要重新登录”“无权限”“origin 不匹配”“会话过期”“会话已使用”和“服务端暂不可用”，且不泄露敏感上下文？

上述问题确定后，新增 ADR 记录协议选择、威胁模型与回退依据；再以 OpenAPI/类型定义固化请求、响应、错误码和测试 fixture。协议未定前不得创建看似正式但无服务端承诺的 endpoint。

## 5. 自动化与人工验收分界

| 可由仓库自动化完成 | 必须由负责人/维护者完成 |
| --- | --- |
| 扩展功能开关、消息契约、origin/nonce 校验和错误状态的单元测试 | 确认 UniPass 后端鉴权依据与改造权限 |
| mock 服务端下的过期、重放、错误用户/账号/origin、限流和撤销回归测试 | 配置目标应用 OIDC/SAML/SSO 或 token exchange 与回调/受众限制 |
| 扩展产物中移除密码解密材料的静态/产物审计 | 提供脱敏测试账号与可用的非生产环境 |
| `npm run verify`、契约测试和新增安全用例 | 在真实 Chrome 中执行登录、失效、切换用户、撤销和回退烟测 |
| 文档、ADR 草案和发布前红绿灯审查 | 对安全、业务影响、灰度范围和上线/回滚作最终审批 |

## 6. 负责人操作步骤

1. **指定协调人。** 由维护者指定一位 UniPass 后端负责人、一位目标应用负责人和一位真实 Chrome 验收人；记录在能力盘点表，不要在仓库提交个人手机号、密码或 token。
2. **完成候选盘点。** 每个候选应用按第 2 节填写一行，并附脱敏认证流程。无法提供一次性消费、origin 绑定或撤销的候选直接标记为“暂不试点”。
3. **选定试点与回退。** 按第 3 节选定一个应用，同时写明旧密码路径是否保留、功能开关默认状态及紧急关闭负责人。
4. **安全评审。** 后端和应用负责人逐项回答第 4 节；确认最短 TTL、单次消费、防重放存储、撤销 SLA、日志字段和限流策略。任何一项未确定时停在设计阶段。
5. **形成可实现契约。** 审批通过后新增 ADR，并由后端提供版本化 OpenAPI/错误码文档和无敏感数据的 mock/测试环境。将安全测试用例纳入后端与扩展 CI。
6. **小范围实现。** 先由扩展在默认关闭的功能开关后接入，保留明确回退；不新增长期 client secret、宽泛 host permission、Cookie 读取或页面常驻脚本。
7. **验收与上线。** 自动化通过后，验收人在独立 Chrome Profile 依次验证成功登录、错误 origin、过期、重放、退出、切换用户、撤权、服务端故障和回退。记录日期、环境和结果，不记录敏感值。
8. **逐应用迁移。** 仅在试点满足第 1 节完成标准后复制模式到下一个应用；每迁移一个应用，删除对应客户端密码解密路径并更新 TD-004 状态。

## 7. 交接给仓库实现前必须提供的最小材料

- 已批准的 ADR 或明确的协议选择记录；
- 已填写的能力盘点条目和试点/回退决定；
- 版本化接口契约、错误码、TTL、单次消费与撤销语义；
- 非生产环境地址、脱敏测试账户获取方式和负责人的验收窗口；
- 功能开关、灰度范围、紧急关闭方式和日志/告警责任边界。

缺少任一材料时，仓库侧只维护本手册与现有密码型安全边界，不开始接入实现。
